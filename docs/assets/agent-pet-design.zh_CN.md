# Agent Pet：AI 工作搭子产品与技术方案

状态：设计提案，尚未实现固件、插件或桥接服务。本文中的协议、资源数值和交互是待验证的设计目标，不代表现有能力。硬件基线：ESP32-C3、8 MB Flash、无 PSRAM、240×320 彩屏、三键、ES8311 音频、Wi-Fi、BLE。基于上游提交 `488beda41309f052d81f08d0016d65a3fd85eb7e`。

手机配网与离开电脑后的跨网使用已纳入交付范围，完整流程见[手机配网与远程使用方案](mobile-remote.zh_CN.md)。

## 1. 产品目标与范围

给同时使用多个 AI 工具的人一个可随身携带的工作搭子：抬眼知道谁在忙、谁需要自己、今天用了多少；按一下回到需要处理的任务。电脑端汇总数据，设备本地表现宠物，不让宠物持续调用模型产生额外费用。

首个数据源为 Magpie，采用适配器接口，后续可接其他 Agent 工具。模型品牌、实际模型 ID 与宠物皮肤独立设置。首个候选皮肤为 DeepSeek 鲸鱼，另预留 Claude 主题角色；正式素材制作前核对官方形象、来源和使用条款，记录授权与署名，不将未经确认的仿作称为官方形象。

| 阶段 | 内容 | 完成标准 |
| --- | --- | --- |
| P0：验证链路 | 模拟事件、USB 绑定、Wi-Fi 连接、加密状态同步、一只占位宠物 | 真实板卡稳定显示状态，断线后恢复，测出内存与功耗 |
| P1a：本地日常可用 | Magpie 真实适配、多个任务、待处理提醒、用量、电脑打开任务、设置与隐私模式 | 连续工作日可用，状态和统计可追溯 |
| P1b：手机与远程 | 手机安全 BLE 配网/登记/换网、热点、中继只读状态、路径切换与撤销 | 无电脑首次配置、不同网络接收状态、来源离线明确标记 |
| P2：增强交互 | 明确支持的回答/取消/重试、语音收件箱、每日小结、更多皮肤 | 逐项核实宿主权限与 API，危险操作仍在宿主审阅 |
| P3：扩展 | 其他工具、多电脑汇总、持续 BLE 网关、端到端加密、签名 OTA | 分别做资源、授权、运维和真机验收 |

默认一台来源电脑绑定一台设备；LAN 优先，离开 LAN 后可选择开启远程中继，局域网功能仍可独立使用。手机可通过安全 BLE 配网，USB 保留为配置与恢复方式。桌面与外出佩戴均纳入场景，佩戴时可切公开模式。Wi-Fi/热点在线无法承诺全天续航；电脑休眠后只能看最后状态，持续更新需来源运行在在线主机。

## 2. 页面、按键与宠物

全新设计应用 UI，复用 BSP 和独立逻辑，不沿用上游硬件测试菜单或页面。

四个主页：此刻、任务、用量、收件箱。顶部显示连接状态与电量；不可用电量显示未知。此刻以宠物为主体，搭配运行数、待处理数和一条重要任务。详情支持滚动，避免长标题挤占整个屏幕。

| 输入 | 主页 | 列表/详情 |
| --- | --- | --- |
| UP / DOWN 单击 | 切换四个主页 | 移动焦点或滚动 |
| OK 单击 | 查看当前页内容 | 打开详情或选中明确操作 |
| OK 长按 500 ms | 打开本地菜单 | 返回上一层 |
| 本地菜单 | 设置、专注/公开模式、摸摸宠物、配网/绑定 | 所有重要操作有文字标签 |

不依赖组合键或双击；单击无需等待额外的双击窗口。语音录制入口在 P2 单独设计，避免长按返回与录音冲突。忘记网络、解除绑定、清除全部数据是不同操作，均二次确认。首次 USB 配置不要求输入长密码。

| 状态 | 宠物表现 | 文字与交互 |
| --- | --- | --- |
| 空闲 | 休息、散步 | 今日概览 |
| 工作 | 翻书、打字或处理工具 | 任务步骤、耗时；步骤未知时显示运行中 |
| 等你 | 举牌看你 | 提问或审核摘要，打开电脑任务 |
| 成功 | 递出成果包 | 结果摘要，可标记已读；验收状态独立 |
| 失败 | 求助牌 | 错误分类、详情入口；不能假称重试成功 |
| 失联 | 无信号图案 | 最后同步时间；不能假装仍在实时工作 |
| 休眠 | 睡觉 | 深睡后不接收实时消息，唤醒重新同步 |

主屏优先级：连接失效横幅始终可见；内容依次选用户等待、失败、运行、未读完成、空闲。同级按等待时长与更新时间确定，用户可固定任务。每个摘要仍保留状态，避免“一个 Agent 等你”被其他运行任务掩盖。

思考、写代码、搜索、测试只在来源明确报告时显示；不能从工具名称猜测成功，也不展示隐私推理内容。无可靠总量时不画百分比。长时间无活动仅标为“可能停滞”，不改成失败。宠物高兴程度不冒充任务结果。

完成通知与验收分离：`completed` 是宿主报告完成，`accepted` 是用户确认成果。成长按验收、整理收件箱等有效行为累计，不按 Token 消耗奖励。不制造断签惩罚、虚假饥饿或消费焦虑。

提醒默认只覆盖新增等待、失败和完成；专注模式仅提醒等待与失败。提醒合并窗口 10 秒，普通声音至少间隔 60 秒；安静时段、音量和亮度由用户设置，默认不播放任务内容。离线积累的完成事件恢复后只汇总一次，不连续响铃。紧急程度是信息优先级，不代表可绕过静音。

## 3. 数据来源与可信度

宿主适配器输出统一数据模型，桥接服务负责归一化、持久化和设备通信。设备不读取会话数据库，不持有模型 API key，不自行推算宿主账单。

| 数据 | 来源与要求 | 缺失处理 |
| --- | --- | --- |
| 任务与运行 | 宿主会话/运行 ID、生命周期事件 | 未知状态，不杜撰进度 |
| Agent/子任务 | 宿主父子关系与状态 | 仅展示宿主确认的层级 |
| 当前步骤 | 明确的工具/阶段事件 | 显示运行中和最近活动时间 |
| 等待用户 | 明确提问/审核事件及仍有效的请求 ID | 不把文本中一个问号当作等待 |
| Token | 宿主增量或累计 usage，注明统计口径 | 显示不可用，禁止两种口径叠加 |
| 费用 | 实际账单或按模型价格估算 | 实际/估算分开展示，无价格则未知 |
| 套餐额度 | 提供方正式接口或宿主明确暴露 | 不用 Token 猜剩余套餐比例 |
| 任务打开 | 宿主可验证的会话定位能力 | 插件提供列表跳转或提示手动打开 |

每项能力通过 `capabilities` 协商。插件只能报告已确认的能力。断线、停止、失败、等待、完成分开；`tool.failed` 不自动等于整个任务失败。父运行费用含子运行时不能再重复加子任务费用。任务结束后仍可能收到迟到 usage，允许修订日报。

任务身份至少包含 `source_id + session_id + run_id`，单独保留父运行和来源事件 ID。同一会话的多次运行不能混为同一个任务。区分目标、单轮运行、后台作业与工作流，记录 `entity_kind`；一轮输出结束只能显示“本轮结束”，不能声称用户目标已经完成。只有来源明确的目标/任务完成事件或用户验收才能升级该实体的完成状态。任务列表在设备保留最多 16 个摘要，优先等待、失败和运行；其余由电脑保留，页面显示总数与省略数。

执行状态和待处理交互正交保存：`execution_state` 与 `pending_interactions` 可同时表示“仍在工作，同时有一个问题等你”。每个交互有 request_id、独立版本、到期/解决状态及 `blocks_execution`；问题到期或解决不必结束运行。屏幕摘要 `state` 可以优先显示 waiting_user，但不清除真实 running 状态。`turn_outcome` 与明确的 `task_outcome` 分开；没有目标完成证据时显示本轮结束/待验收，不播放目标成功动画。来源新鲜度 `fresh/stale/unknown` 独立于任务结果，断线不覆盖最后已知结果。

Token 不能仅按事件去重：对齐 DSH meter 的稳定记录身份、版本和替换/覆盖关系，upsert 后重算受影响聚合。最终累计非负，但修订差额可以为负；重复、重试、失败尝试、被替换记录是否计费遵循来源语义，不猜账单。缺少可用归约接口时，先验证脱敏样本并实现等价归约，再开放统计。P1 承诺可核实的 Token；费用是可选估算，实际账单仍不可用。

费用使用整数微货币单位，线上用十进制字符串表示，例如 USD 的 `"1840000"` 表示 1.84 USD；金额带币种、实际/估算标签、价格表版本及数据时间。Token 累计量同样使用非负十进制字符串，避免跨语言整数精度问题。USD 与 CNY 不直接相加；人民币展示需带汇率来源与日期。未知值为 `null`，绝不显示成零。

日报按电脑设置的 IANA 时区分桶，午夜通过新快照切换，支持夏令时。连接耗时/任务运行耗时用单调时钟结合宿主时间，设备本地时钟不决定账单归属。价格修订、统计缺口和来源覆盖范围在电脑设置页可查看。

## 4. 系统架构与责任边界

```mermaid
flowchart LR
  M[Magpie 与其他工具] --> A[来源适配器]
  A --> B[电脑桥接服务]
  B --> D[本地状态库与统计]
  B <-->|局域网 WSS| P[AI Passport]
  P --> U[本地宠物与页面]
  P -. USB 首次配置与恢复 .-> B
  B -->|受限动作| A
```

- Magpie 插件：订阅允许的数据事件、输出能力、定位任务；在宿主允许时执行明确操作。
- 桥接服务：设备配对、WSS 服务、mDNS、数据归一化、快照、动作校验、用量聚合、日志脱敏。
- 设备：Wi-Fi 客户端、WSS 客户端、固定大小状态缓存、宠物动画、通知和按键；不负责全量历史。
- 电脑设置界面：选择来源与项目、配置网络、调整预算、查看在线状态、撤销设备、导出脱敏诊断。

桥接服务是独立逻辑边界，可以在确认宿主插件运行时支持后内置，也可以作为本机 sidecar。不能默认插件有任意 Node.js socket 权限、串口权限或长期后台生命周期。宿主接入证据见第 14 节。

适配器与桥接服务跨进程时走只绑定 loopback 的已认证 IPC，优先系统本地 socket/命名管道及用户权限；若用本机 HTTP，使用独立会话令牌、固定方法与 Origin 校验。设备服务与管理 API 分端口/绑定地址，管理界面不暴露到局域网。

首版桥接服务手动启动，明确显示进程与插件连接状态；开机自启作为可选设置。卸载插件不应遗留无限运行的后台进程。插件关闭、Magpie 退出与整台电脑休眠是三个不同状态。

## 5. 网络方案与首次使用

**LAN 主链路：设备作为 Wi-Fi STA 主动连接电脑 WSS；远程链路：电脑与设备分别出站连接中继 WSS 443。** 不搭 MQTT broker，不依赖家中端口映射。手机安全 BLE 配网与 USB 均作为正式配置路径，BLE 仅在限时配网页开启，避免长期争用内存。以下 USB 流程保留，手机首次登记与远程流程见[移动方案](mobile-remote.zh_CN.md)。

首次使用流程：

1. 电脑启动桥接服务，用户通过数据线连接设备，在设置页选择正确串口；打开串口可能触发板卡复位，先明确设备并提示。
2. 设备进入限时配对页，显示一次性绑定标识；电脑与设备展示同一短码，用户在设备按 OK 确认。短码只是确认，不作为加密密钥。
3. 电脑经 USB 下发选定的 2.4 GHz SSID/密码、桥接服务 ID、私有 CA/证书公钥信任信息、每设备随机凭证、端口、当前地址候选与首次可信时间。协议区分二进制配置帧和普通日志，禁用回显，不把凭证写入日志。
4. 配对窗口默认 120 秒，敏感配置仅在窗口内、且经物理确认后生效。已有绑定不能被新电脑静默替换。
5. 设备连接 Wi-Fi，取得 DHCP 地址，验证服务端身份并完成设备认证，下载快照；电脑显示“网络已连 / 服务已连 / 数据已同步”三个结果。
6. 成功后可以拔掉 USB。USB 连接电脑并不等于完成 Wi-Fi 配网；仅供电时不承诺数据链路。

保存最多 3 个由用户配置的网络，只自动连接列表内网络；默认不自动接入开放网络。凭证存储于专用应用配置命名空间，掉电保留；实际 Flash 加密/NVS 加密的可用性与恢复方式实施时验证，首版不能宣称具备物理防提取能力。

电脑需要允许桥接端口的局域网入站连接，桥接服务只绑定选定私有网卡，VPN/公网接口默认排除。不自动修改防火墙或路由器。桥接端口初始建议 `7443`，冲突时选新端口，经可信配置通道更新设备。

| 场景 | 行为 |
| --- | --- |
| 家庭/办公室同一 LAN | Wi-Fi + WSS 正常使用，无需互联网也能传状态 |
| 电脑走有线、设备走 Wi-Fi | 路由器允许跨接口互访即可 |
| 手机热点 | 出门时仅设备加入手机 2.4 GHz 热点，经中继连接家中在线电脑；两者恰好同热点时也可验证 LAN 路径 |
| 只有 5 GHz 的网络 | 设备无法连接；使用 2.4 GHz 或兼容混合网络 |
| 访客 Wi-Fi / AP 隔离 | 可能无法访问电脑；提示网络隔离，不反复要求重输密码 |
| 企业 802.1X / 网页认证 | 首版不支持，使用个人热点或专用网络 |
| VPN / 多网卡 | 选正确私网接口，显示设备可达地址，避免广播到无关网段 |
| 不同地点或不同网段 | P1b 经可选中继接收状态；未开通/不可达时明确离线 |
| 电脑睡眠 / 关机 | 本地状态变旧；若任务在云端继续运行，设备也无法经睡眠电脑获取更新 |

发现服务使用 `_agentpet._tcp.local` mDNS，广播仅含服务 ID、端口和协议版本，不广播用户名、项目或凭证。mDNS 只是地址候选，不能改变绑定身份。优先尝试上次地址，再 mDNS；跨网段或 mDNS 不通时允许 USB 设置 IP/主机名。DHCP 变化后按相同信任身份重连；新证书、新电脑不能自动被信任。

USB 持续数据传输可作为 P1 的独立备选适配器，必须完成双向帧协议、权限和复位行为验证后再开放。不能将“存在 USB 日志接口”当作完整备用链路已经可用。手机 BLE 配网属于 P1b，P0 先核实维护中的安全 provisioning 与手机 SDK。上游 BLUFI 可作网络配置参考，但不代表账户/所有权/中继登记已支持；完整信任流程见[移动方案](mobile-remote.zh_CN.md)。

## 6. 信任、认证与撤销

WSS 使用 TLS 1.2 或更高。每个桥接实例有独立私有 CA/服务证书和稳定服务身份，通过 USB 写入信任根及公钥指纹；设备验证证书链、服务名称、有效期和绑定公钥。稳定的证书名称与当前连接 IP 分离，按固定名称验证。手机首次绑定可通过物理确认的安全 BLE 会话建立信任；中继另用正式域名证书、独立凭证与预置签名信任，远程与 LAN 不混用身份。ESP-IDF/mbedTLS 与 WebSocket 客户端能否同时完成这些校验是 P0 验证项，禁止以关闭证书校验交付。

冷启动没有可信 RTC 时间，持久化旧时间不能冒充当前时间。首次 USB 给出时间；以后冷启动/深睡恢复先尝试已绑定电脑的签名时间引导：独立 HTTP 端口初始建议 `7444`，仅开放 `/v1/time`，请求携带设备新生成的 256 bit 随机 nonce，响应包含固定协议域 `agentpet-time-v1`、bridge ID、原 nonce、整数 UTC 秒与签名。用 USB 绑定的公钥验证固定编码载荷（协议域、受限字符 bridge ID、nonce 十六进制、十进制秒，按换行连接，无尾换行），验证耗时不超过本地单调时钟 5 秒。签名格式在实现协议 schema 中固定为 ECDSA P-256/SHA-256 与 DER 签名，设备限制响应长度。只接受绑定身份、匹配 nonce 的新响应，防止重放；此端点不接收凭证、不提供任务数据，限速且不修改配对。

签名证明时间来自已信任电脑，不证明电脑时钟绝对正确。取得时间后仍完成正式 WSS 证书链、名称、有效期和公钥校验；服务证书签名密钥与绑定公钥的对应/轮换必须一起验证。主链路 mDNS 可声明时间端口，但不能声明新的信任公钥。P0 必测断电后无互联网的冷启动与深睡恢复；若签名引导尚未实现/失败，明确要求 USB 修复时间，不能依赖无认证 SNTP 或静默关闭校验。根/公钥轮换经已认证授权通道或 USB 重新绑定；丢失旧信任必须物理确认。

设备通过 TLS 内的 `auth` 帧提交每设备至少 256 bit 随机凭证，服务验证通过后才处理业务帧；不放 URL、mDNS 或日志。认证超时 5 秒，认证失败断开并退避；未认证连接有并发和速率上限。凭证在电脑由系统安全存储或受限用户文件保存，设备不得含提供方 API key。

设备被撤销后立即断开，电脑拒绝旧凭证。设备显示已解除授权，不自动重新注册。设备侧“解除绑定”销毁本地凭证；电脑侧仍需管理吊销记录。恢复出厂清理网络、绑定和私人缓存，但不会自动撤销遗失设备在电脑端的授权，设置页应提示。

本地存储物理提取、被控制的电脑和恶意固件不在首版防护承诺内。公开模式隐藏项目名、问题正文、费用和身份信息；通知音不播报这些信息。

## 7. 协议 v1 草案

UTF-8 JSON，经 WSS 传输；不发送模型 Token 流、不传图片帧、不压缩 WebSocket 消息。资源在设备本地，动画由状态驱动。版本与能力协商成功前不执行动作。未知可选字段忽略；不支持的主版本拒绝并显示需升级。

统一帧包含 `v`、`type`、`message_id`、`stream_id`、`revision` 与 `payload`。`stream_id` 标识每台设备过滤后视图的发布流世代；状态库重建、过滤策略改变或发布队列不可恢复时变化，普通重连保持。`revision` 是该设备发布流的连续序号，不是宿主事件序号或全局数据库版本。先做权限过滤、前 16 项选择和刷新合并，再为实际发布的 `state.delta` 分配下一个 revision；未发出的中间状态不占号。心跳和控制帧带当前已发布 revision，不占用新 revision。序号达到 JSON 安全整数上限前切换新 stream。服务重建或任何数据缺口都以快照恢复。

发布流维护自己的已发布投影。快照冻结这一投影及基准 revision，未发布变更在快照结束后顺序编号发送；若需跳到最新底层状态，则切新 stream 并发送新快照。不能把全局变化计数用作该流序号，否则过滤、合并和视图截断会制造永久缺号。

连接顺序：TLS → `hello`（版本、设备 ID、固件版本）→ `auth` → `welcome`（来源能力、服务/适配器状态、时间与限制）→ 分页快照 → 增量。

| 类型 | 方向 | 作用 |
| --- | --- | --- |
| `hello/auth/welcome` | 双向 | 协商、认证、能力与状态 |
| `snapshot.begin/page/end` | 电脑 → 设备 | 原子替换任务、用量、收件箱与当前状态 |
| `state.delta` | 电脑 → 设备 | 完整替换单个摘要、删除摘要或替换聚合；不依赖 JSON Patch |
| `heartbeat` | 电脑 → 设备 | 存活、来源新鲜度、当前 revision |
| `ack/resync` | 设备 → 电脑 | 已应用 revision 或请求重同步 |
| `action.prepare/action.offer` | 双向 | 进入详情时获取新鲜操作描述与短期 token |
| `action/action.query/action.result` | 双向 | 执行、按 ID 查询与明确结果 |
| `view.configure/view.ready` | 双向 | 隐私模式和 view_epoch 确认，随后新快照 |
| `device.status` | 设备 → 电脑 | 电量、连接质量、固件版本；不包含 Wi-Fi 密码 |

任务增量示例（所有 ID 均为示例值）：

```json
{
  "v": 1,
  "type": "state.delta",
  "message_id": "msg-43",
  "stream_id": "stream-demo",
  "view_epoch": "view-demo",
  "revision": 43,
  "payload": {
    "op": "task.upsert",
    "task": {
      "id": "magpie:session-demo:run-demo",
      "entity_kind": "turn",
      "state": "waiting_user",
      "execution_state": "running",
      "pending_interactions": [{"request_id": "request-demo", "revision": 1, "blocks_execution": false}],
      "state_revision": 9,
      "title": "Website update",
      "phase": "needs_input",
      "progress": null,
      "updated_at": "2026-11-05T06:30:00Z",
      "request_id": "request-demo",
      "available_actions": ["open_on_host"]
    }
  }
}
```

任务状态枚举：`queued/running/waiting_user/completed/failed/cancelled/unknown`；审核/验收/已读是独立字段。阶段可选，进度仅在宿主提供可靠计量时为 0..1。`task.upsert` 发送该摘要的完整替换对象；删除用显式 `task.remove`。

初始限制：单条完整消息最大 4096 字节，分片总长也不得超过此值；标题最大 96 UTF-8 字节，摘要最大 256 字节，任务最多 16、待处理项最多 8、每项操作最多 4。截断在 UTF-8 字符边界完成。字符串按纯文本显示，拒绝控制字符、超深对象和异常数组；动态中文不在字体中时用可见占位及电脑详情入口，不隐藏缺字问题。

快照最多每页 4 个任务，仍以字节限制为准；还分页传输用量与收件箱。`begin` 给出快照 ID、基准 revision、页数与各类对象数量；`page` 带 ID 和页序号；`end` 确认完整。设备以固定大小暂存模型接收，全部校验后一次切换；旧画面保留但标为同步中。10 秒未完成、数量不符、缺页或重复页内容矛盾均丢弃暂存并请求重同步。

桥接服务在快照期间缓存基准 revision 之后的增量，结束后顺序发送；队列溢出则中止并重建较新快照，绝不交付有缺口的状态。设备只接受当前 stream 的连续业务 revision，重复的忽略，缺号请求 resync。每次重新连接默认完整快照，首版无需设备保存事件日志。心跳若指示服务端 revision 高于已应用值且无快照进行，也触发缺口恢复。

非关键刷新合并到最多每秒 2 次，等待/终态立即入队。64 条待发队列仅在电脑桥接端，且每连接总字节上限 64 KB，先到任一上限即回压；设备不能存 64 条完整消息。队列溢出丢弃可重建状态并切新 stream/快照，动作结果保留在电脑并可按 ID 查询。同一事务内前 16 项成员变化、删除/新增及相关计数要原子应用；`state.delta` 可携带受 4096 字节约束的 ops 数组，无法容纳的事务改用快照，避免过渡视图超限或计数矛盾。

设备只保留一条 4096 字节重组缓冲、上限 8 KB 的有界解析工作区；状态与通知队列保存定长命令/ID，不保存完整 JSON，建议总上限 2 KB。当前与暂存模型合计先预留上限 40 KB，schema/结构体落地时核算字符串、交互和操作描述总量，不能只限制任务数。无法装入模型则按协议缩减协商容量，不反复 OOM 重连。固定队列、模型容量和速率目标必须在真机测量后调整。

## 8. 心跳、离线与多层状态

应用心跳每 15 秒一次，45 秒无有效帧标记连接失效并重连。远程模式还独立检测来源心跳；中继在线不能使电脑旧状态变新，LAN/远程切换后的完整快照和冷启动时间按[移动方案](mobile-remote.zh_CN.md)处理。不能只依赖 Wi-Fi 已连接图标；界面区分 Wi-Fi、桥接连接、来源适配器和任务活动。桥接在线但 Magpie 插件掉线时，保持网络图标，显示来源离线，任务转为陈旧显示，不能假定取消或完成。

重试间隔 1、2、4、8、16、30 秒封顶，加入 ±20% 随机抖动；稳定 60 秒后清零。Wi-Fi 连接、TLS、认证和快照都有独立超时与错误码。认证/协议不兼容提示配置错误并降低重试频率，避免无限快速循环。无线认证失败与 AP 不可达分开处理。

设备重启后只显示本地宠物与等待连接，不把缓存的任务当作实时状态。快照恢复不重播历史完成音；运行中出现的新终态依通知 ID 去重，内存保留最近 32 个通知 ID。设备重启可能丢失该去重缓存，因此首次快照永远静默，电脑保存通知已读状态。

桥接服务持久化受限的归一化摘要、来源游标、费用聚合和动作结果。默认已结束摘要保留 7 天、每日聚合保留 30 天，可清除；保留等待/运行任务直到来源确认结束或用户隐藏。原始对话与工具输出不复制。崩溃后从宿主快照/游标重建；若来源不支持回放，明确标记统计缺口。

## 9. 按键动作与一致性

P1 允许设备本地操作及 `open_on_host`；宿主跳转 API 不可用时显示手动定位信息。回答、取消、重试默认不开放，只有宿主公开接口、权限和过期语义均核实后才通过能力开启。部署、删除、付费、发布、凭证输入等需详细审阅的操作留在宿主。

摘要中的 `available_actions` 只是能力提示，不是执行凭证。设备进入详情或用户准备操作时发送 `action.prepare`，电脑返回 `action.offer`，包含类型、标签、目标/交互版本、不透明 token、过期 UTC 时间、允许参数 schema 与是否需要本地确认。只在详情页即将操作时取新 token；30 秒到期后重新 prepare，不能让一直未变化的任务永远失去操作入口。离线只允许本地查看。

每个远程动作包含随机 `action_id`、`device_boot_id`、目标 ID、目标 `state_revision`、对应 `request_id`、动作 token、类型与显式参数。电脑记录 token 的到期时间及参数约束，过期由电脑时钟判定，不信任设备自报 TTL。一般有效期 30 秒，状态变化即时撤销。`action.query` 携带 action ID 查询记录；已过保留期返回 unknown，不能按新动作执行。

桥接服务重新检查设备授权、来源能力、目标版本和动作 token，再向宿主执行。ACK 只表示收到了；结果区分 `accepted/succeeded/failed/expired/conflict/unsupported/unknown`。`accepted` 不代表已经执行成功。屏幕只有收到确认结果或对应新状态才显示成功。

电脑先持久化动作意图与 executing 状态，再调用宿主，最后持久化结果；崩溃恢复时未决 executing 先视为 unknown 并查询。电脑保留动作 ID 与参数哈希/结果最多 7 天，同 ID 同参数返回已有结果，同 ID 不同参数拒绝。设备仅在同次启动、连接恢复且 token 仍有效时用原 ID 重发；最多 4 个待处理动作，离线不新建远程动作、不排队过期回答。电脑执行宿主操作后崩溃且未记录结果时，若宿主无幂等接口，则结果为 unknown，查询状态或让用户检查，不自动再执行；不承诺跨系统 exactly-once。

## 10. 资源、声音与省电

宠物动画建议 64×64 或 80×80，RGB565/索引色压缩素材留在 Flash，按需解码，初始目标 6–10 fps，只刷新变化区域。80×80 RGB565 一帧约 12.8 KB；不能把所有帧解码后常驻 RAM。字体按界面固定文字及动态标题需求选取，中文覆盖、实际控件字体和设备渲染分别验收。

网络任务、状态归约、音频任务与 LVGL 解耦，通过有界队列通信。网络与按键回调只入队；非 LVGL 线程访问对象持 BSP 锁；退出页面先停止访问 UI 的任务/定时器。Wi-Fi、TLS、字体、音频与 DMA 共同预算，不预设所有功能可同时满负荷运行。

P0 先测现有 BSP 启动后的 free heap、最小 free heap 和 largest free block，再逐步加入 Wi-Fi、TLS、同步、宠物、通知音。设计保护目标：峰值负载后空闲堆至少 32 KB、最大连续块至少 16 KB，且所有预期分配成功；这些是待验证门槛，不能代替实际 TLS 分配分析。若达不到，先减少动画/缓存和并发，保留核心状态功能。网络消息处理与快照使用固定上限，TLS 握手期间暂停非必要音频/动画分配。必须在当前/暂存模型驻留、最长转义中文消息、网络抖动与反复 TLS 握手同时发生时测试；仅测稳定在线后的余量不算通过。

首版仅短提示音，按需初始化/播放并安全暂停；音频出错仍可看屏。语音 P2 优先短时按键录音、分块上传，禁止先缓存整段长录音。基础 16 kHz/16 bit/单声道约 32 KB/s；30 秒约 960 KB，不能按整段内存缓存设计。后续音频与状态消息分通道、有独立背压，语音不得堵住等待提醒，录音时明确显示并允许取消。

桌面模式保持在线，闲置后降低亮度和动画频率。便携模式可减少刷新并使用经验证的调制解调器省电策略；深睡时 WSS 会断开，无法接收即时通知，唤醒后重新连接同步。只有实测完成才给出续航小时数。低电量阈值初始建议 20% 提醒、10% 减少非必要表现，SOC 不可信时不做强制关机判断。

## 11. 隐私、诊断与更新

设备默认接收经过筛选的标题、状态、汇总用量和允许操作，不接收代码、完整提示词、原始回复、推理内容、密钥和工具输出。用户在电脑选择允许的项目与字段；可使用项目别名。

隐私切换具有独立 `view_epoch`：设备进入公开模式立即遮蔽并擦除私人当前/暂存模型、队列和待播内容，即使离线也生效；创建新 epoch，发送 `view.configure(mode, view_epoch)`。电脑清掉旧发布队列，返回相同 epoch 的 `view.ready` 和过滤后的新 stream/快照。所有含业务内容的帧必须带 view_epoch，设备拒绝旧 epoch，避免迟到快照重新填入私人信息。离线时保持只有本地宠物的公开画面。恢复私人模式需设备确认和新 epoch/快照，不能恢复被隐藏的旧缓冲；电脑不能静默关闭设备公开模式。开机先显示通用画面，直到当前模式同步完成。

日志记录错误类别、脱敏 ID 和耗时，不打印凭证、录音、正文或带 token 的 URL。诊断导出由用户触发，可查看脱敏预览。设备不自动上传遥测；桥接服务不对公网监听。远程开启时经出站连接上传用户允许的最小摘要，中继作为受信任处理方可能读取这些字段，首版不宣称端到端加密；字段、24 小时快照 TTL、撤销与删除策略见[移动方案](mobile-remote.zh_CN.md)。

首版使用 USB 固件更新，保留上游最小分区。刷写是否保留 NVS 按实际镜像方式说明，合并镜像可能清除配对/网络配置，不宣称必然保留。升级前导出非敏感设置和记录恢复步骤。协议支持主版本拒绝与能力降级；设备设置里显示固件/协议版本。

OTA 属 P3：需重新预算双应用分区与素材体积、签名验证、回滚、断电恢复和证书轮换。不能将网络上下载 bin 直接刷写当作安全 OTA。

## 12. 验收与实施顺序

1. 验证宿主事件/用量/跳转接口，做来源能力矩阵和模拟器；取得真实脱敏样本。
2. 用占位 UI 打通 USB 配置、Wi-Fi、TLS、认证、分页快照、增量和心跳，测资源。
3. 做独立任务状态机、去重、用量归一化、动作幂等逻辑与 host tests；实现自有 UI。
4. 接真实 Magpie 数据，验证同会话多次运行、多个 Agent、来源断连、费用迟到修订。
5. 加入宠物素材、通知、安静时段和公开模式，完成 P1a。
6. 完成 P1b 手机安全配网、无电脑登记、账户/中继、热点、路径切换和移动验收；P0 已先验证其关键资源与信任路径。
7. 最后再加语音与宿主明确支持的可写操作。

| 验收组 | 必须覆盖 |
| --- | --- |
| 配网与绑定 | 首次配置、拒绝绑定、超时、错误密码、无 2.4 GHz、重启、清除网络与独立撤销绑定 |
| 网络恢复 | 断路由器、DHCP 换 IP、mDNS 被禁、AP 隔离、电脑睡眠/唤醒、插件退出、桥接重启 |
| 信任边界 | 未授权客户端、错误设备凭证、冒名 mDNS、证书错误/过期/轮换、无可信时间、撤销后重连 |
| 数据正确 | 重复/乱序/丢失增量、分页快照缺页/超时/溢出、跨 stream、任务超过 16、超长中文与缺字 |
| 动作正确 | 双击重复、过期请求、状态已变、设备掉电、宿主执行后桥接崩溃、结果未知、能力不支持 |
| 用量 | 增量/累计、缓存口径、父子任务去重、跨币种、未知价格、迟到修订、跨午夜与夏令时 |
| 设备 | 中文实际渲染、三键手感、通知合并、静音、录放音、Wi-Fi/TLS 峰值内存、低电量与长期运行 |
| 手机与远程 | iOS/Android 配网、无电脑登记、跨账户隔离、热点、来源睡眠、远程冷启动、路径切换、缓存过期与撤销；详见移动方案 |
| 性能目标 | LAN 稳定时事件到画面 p95 ≤2 秒；45 秒内显式失联；网络恢复后目标 30 秒内重同步；24 小时无持续泄漏 |

额外回归：运行同时等待非阻塞问题；本轮结束但目标未完成；meter 记录替换/重试/负向修订及跨日归属；被过滤或合并的事件不制造序号缺口；Top-N 变化原子更新；断电无互联网时间引导；详情停留超过 30 秒后刷新动作；调用前意图落盘与调用后崩溃；同步中/离线/旧帧在途时切公开模式；满缓存重握手不 OOM。

性能目标是验收目标，重连时延依 Wi-Fi、DHCP、TLS 和退避而变化。记录测试条件与实际数值，不能用单次演示宣称通过。实现后运行仓库完整 gate；固件构建、主机测试与设备验收分开报告。刷机须明确固件、目标和数据影响并取得授权。

## 13. 暂定选择与待决定事项

可按默认值推进：一台来源电脑一台设备，LAN 优先、可选远程中继、手机 BLE 与 USB 配网、只读状态优先、主屏一只宠物、资源本地化、无 OTA、声音可关闭。P1b 手机/远程是明确交付项；实际服务部署前确定域名、运营方、地区、费用和数据策略。

开始实施前仍需验证：Magpie 实际插件 API 与运行权限；可用串口与板卡型号；真实 usage 的口径；TLS 校验和峰值内存；中文字体覆盖；电脑/设备所用网络的互访能力。角色可以先用原创占位素材，不阻塞协议开发。

后续产品选择：鲸鱼/Claude 主题首发皮肤、重点模型与工具、首批手机系统、托管/自托管中继和部署地区。离开电脑网络后继续接收提醒已纳入范围；来源在线仍是实时更新的前提。

## 14. Magpie 接入证据与未决接口

已只读检查当前安装的 DSH `0.2.2-rc.1` 打包实现；这是当前版本实现证据，不等于稳定公开 SDK 或已完成插件验证。源码模块均位于 `@deepseek-ai/` 命名空间，以下位置为模块内路径与行号，升级后需重验。

| 能力 | 当前实现证据 | 集成决定 |
| --- | --- | --- |
| 会话事件 | `dsh-session/lib/index.js:1583–1601` 发布 `session/event`；session projection 提供快照/变更机制 | 服务端适配器观察事件与注册表，回调仅入队，不读取个人数据库 |
| Agent 状态 | `dsh-agent-loop/lib/index.js:554–563` 为 idle/running；提供 turn/step 生命周期 | idle 不等于任务完成；工具失败不直接改为任务失败 |
| 多类任务 | goal/change、todo/write、workflow、后台 job 事件；`dsh-jobs-local` 提供订阅 | 分别归一化实体类型与父子关系，不拼出虚假统一完成信号 |
| Token | `dsh-token-meter/lib/index.js:317–345` 分未缓存输入、输出、缓存读、缓存写；后续归约处理替换/重试 | 复用或严格对齐现有归约，不能把每个流式 chunk 相加 |
| 费用/套餐 | 本轮没有核实实际账单和剩余额度接口 | 费用先标估算；无价格或无覆盖时未知 |
| 等待问题 | `dsh-user-questions/lib/index.js:676–712` 请求 waterfall；限时问题可能继续运行，历史投影不覆盖所有阻塞问题 | 只观察并原样委托给原答题者，不能拦截/代答；等待与运行正交 |
| 审核 | `dsh-user-approval` 有 asked/decided/request 生命周期 | 首版只提醒，保留宿主审核流程 |
| 打开会话 | `dsh-client-ui-workspace/lib/client.js:1473–1475` 有 `uiWorkspace.openSession` | 需要客户端 companion；仅确认页面切换，未确认系统窗口前置/原生 deep link |
| 网络桥接 | `dsh-host-webserver` 有路由/upgrade 注册，但桌面组合未必启用该服务 | 优先独立 sidecar；内置网络与串口权限需插件打包后验证 |

推荐拆为小型服务端来源适配器、可选客户端 companion、独立桥接服务三部分。服务器适配器输出最小脱敏摘要；companion 处理当前会话选择和打开会话意图；sidecar 承担设备网络。现有 JSON-RPC SDK 不足以证明外部进程可被动订阅桌面中所有已有会话，不能用它替代宿主插件验证。

尚未验证：插件安装/装配点、每个来源投影的可访问性与作用域、窗口前置、串口绑定界面、生命周期与热卸载清理、真实费用来源、远程答题/取消的受支持入口。无接口时先使用模拟器完成设备链路，再决定补接口或接受受限能力。
